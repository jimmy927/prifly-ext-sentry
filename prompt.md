Sentry: a session started from a Sentry issue carries that issue on its banner in prifly, and the first prompt holds the issue — counts, first and last seen, releases, tags, the latest event's stack trace (in-app frames, library frames folded), breadcrumbs and request. The whole latest event is saved as JSON beside it on disk, with every frame, local variable and breadcrumb: read it when the trimmed trace is not enough. The issue can be resolved or ignored from its chip in prifly, so do not resolve or ignore it yourself unless you are asked to. The `sentry` skill searches issues and reads other issues and events from the command line; it uses the reader's own Sentry login, which prifly keeps in its vault as the entry `sentry`: run the skill's script through the `vault_run` tool with `entry: "sentry"` (it sets the token for that one command), and never ask them for a token.
