Sentry: a session started from a Sentry issue carries that issue on its banner in prifly, and the first prompt holds the issue — counts, first and last seen, releases, tags, the latest event's stack trace (in-app frames, library frames folded), breadcrumbs and request. The whole latest event is saved as JSON beside it on disk, with every frame, local variable and breadcrumb: read it when the trimmed trace is not enough. The issue can be resolved or ignored from its chip in prifly, so do not resolve or ignore it yourself unless you are asked to. For other issues and events use the `sentry_search`, `sentry_issue`, `sentry_events` and `sentry_event` tools (`sentry_event` with `save` writes the whole event JSON to your scratchpad). They read with the reader's own Sentry login, which the extension holds: you never see or need a token, and never ask the reader for one. If a tool says Sentry is not logged in, tell the reader to log in from “From a Sentry issue…”.
